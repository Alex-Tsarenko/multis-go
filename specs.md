# Спецификация локального Go-агента (Multis.Agent)

## 1. Архитектура системы

- **Фронтенд (Web UI):** Одностраничное приложение (HTML/JS/CSS), встроенное в исполняемый файл Go с помощью директивы `//go:embed`.
- **Бэкенд (Go):** Единый бинарный файл, включающий веб-сервер (`net/http`) и рантайм управления жизненным циклом агента (`Multis.Agent.Runtime`).
- **Связь и транспорт:**
  - REST API (JSON) для инициализации сессий, передачи пользовательского ввода и команд управления.
  - **Server-Sent Events (SSE):** основной канал доставки данных в реальном времени (потоковые токены рассуждений reasoning-моделей, вывод основного ответа, статусы вызовов инструментов).

## 2. Ключевые компоненты бэкенда

### 2.1. Изоляция ядра программы и слои абстракции (интерфейсы-переходники)
Согласно архитектурным правилам, ядро `Multis.Agent.Runtime` полностью изолировано от конкретных реализаций ввода-вывода и внешних провайдеров через интерфейсы:
- `FileSystem`: чтение, запись, проверка путей, получение метаданных файлов.
- `CommandExecutor`: выполнение внешних команд с контекстом (`context.Context`), ограничением времени и буферизацией вывода.
- `AIClient`: взаимодействие с API LLM, поддерживающее стриминг и структурированный Tool Calling.

### 2.2. Безопасность песочницы (Sandbox & Path Validation)
Для предотвращения атак Directory Traversal (`../`) и выхода за границы рабочей директории:
- Запрет простой проверки через `strings.HasPrefix`.
- Обязательная нормализация путей через `filepath.Clean` и `filepath.EvalSymlinks`.
- Валидация вхождения целевого пути в разрешённую рабочую директорию (`workspace`) через `filepath.Rel`:
  - Путь считается валидным только если относительный путь не начинается с `..` и не равен пустой строке вне корня проекта.
- Защита от опасных/интерактивных команд в `CommandExecutor` (запрет `vim`, `less`, интерактивных шеллов).

### 2.3. Поддержка Reasoning-моделей и протокол SSE
Потоковая передача данных клиенту реализуется через `http.Flusher` с поддержкой отмены через `r.Context().Done()`. Слой провайдеров (`Multis.Agent.Providers`) принимает идентификатор модели из конфигурации и не зависит от конкретной версии.

Формат событий (`text/event-stream`):
- `event: reasoning` — чанки цепочки рассуждений (`reasoning_content`) для моделей с механизмом рассуждений (например, `deepseek-reasoner`). Для стандартных быстрых моделей (например, `deepseek-chat`) событие пропускается: `{"content": "..."}`.
- `event: message` — чанки основного текста ответа (`content`): `{"content": "..."}`.
- `event: tool_call` — структурированные данные вызова инструмента (`id`, `name`, `arguments`).
- `event: tool_result` — результат работы инструмента (`status`, усечённый `output`).
- `event: error` — ошибки выполнения или превышения лимитов (`message`).
- `event: done` — маркер завершения шага (`finish_reason`).

### 2.4. Управление контекстом и защита от зацикливания
- Ограничение размера вывода инструментов (усечение/truncation вывода терминала и длинных файлов) перед добавлением в историю сообщений для предотвращения переполнения контекстного окна.
- **Детектор зацикливания (LoopDetector):** отслеживание повторных идентичных вызовов инструментов с одинаковыми аргументами. При превышении порога повторений цикл прерывается с `finish_reason: "loop_detected"`.
- Лимит шагов в цикле ReAct (`max_steps`, по умолчанию 50) как верхний предохранитель.

## 3. Стратегия тестирования

- **Unit & Integration (Go):**
  - Пакеты `testing` и `net/http/httptest`.
  - Изолированное тестирование логики `Runtime` с использованием in-memory реализаций интерфейсов `FileSystem`, `CommandExecutor` и `AIClient` (без доступа к диску и внешним сетям).
  - Проверка гонок состояний: запуск с флагом `go test -race ./...`.
- **E2E-тестирование:**
  - Тестирование связки реального встроенного UI и Go-сервера в headless-режиме через Playwright.

## 4. Сборка и поставка

- **Команда сборки:** `go build -o agent main.go`
- **Результат:** Единый статически слинкованный бинарный файл (10–15 МБ), готовый к запуску на машине пользователя без внешних зависимостей (Docker, Node.js, Python).
